# TradeBot

Telegram-бот на [node-telegram-bot-api](https://github.com/yagop/node-telegram-bot-api) для просмотра баланса и открытых фьючерсных позиций на биржах [MEXC](https://www.mexc.com/) и [BingX](https://bingx.com/).

## Возможности

- `/balance` — запрашивает фьючерсный баланс USDT на MEXC и BingX (подписанные запросы к приватным Futures API обеих бирж) и присылает баланс по каждой бирже.
- `/status` — запрашивает открытые фьючерсные позиции на MEXC и BingX (символ, сторона, объём, цена входа, плечо, цена ликвидации; для BingX дополнительно нереализованный PnL) и присылает список по каждой бирже.
- `/trade` — включает автоторговлю арбитражем (см. ниже). `/stop` — выключает её; если в этот момент открыта позиция, бот немедленно закрывает её по рынку на обеих биржах.
- `/start` — подписывает чат на уведомления о спотовых сделках и арбитражных возможностях.
- Уведомления о спотовых сделках на MEXC: бот открывает приватный WebSocket user data stream MEXC (канал `spot@private.deals.v3.api`) и присылает сообщение по каждой сделке всем, кто написал `/start`. Настраивать торговые пары не нужно — приходят сделки по всем парам аккаунта, независимо от того, кем они были совершены — вручную или грид-ботом.
- Автоторговля арбитражем на фьючерсах MEXC/BingX: пока не включена команда `/trade`, бот **ничего не отслеживает и не присылает** — арбитражные уведомления в режиме «просто наблюдения» не поддерживаются. После `/trade` бот раз в `ARBITRAGE_POLL_INTERVAL_MS` (по умолчанию 60 сек) опрашивает публичные тикеры фьючерсов обеих бирж, сопоставляет общие пары, и при превышении разницы цен `ARBITRAGE_THRESHOLD_PERCENT` (по умолчанию 3.2%) **реальными сделками** открывает лонг на более дешёвой бирже и шорт на более дорогой — маржа 1 USDT и плечо 2x на каждой (объём округляется вверх до минимального лота биржи, поэтому реальная маржа может оказаться больше 1 USDT). Перед открытием бот заранее оценивает требуемую маржу под минимальный лот каждой биржи и сверяет её с доступным балансом (с запасом 10%) — если баланса не хватает хотя бы на одной из бирж, пара пропускается с уведомлением, а не открывается вслепую. Бот также сверяет funding rate обеих бирж: если чистый funding против позиции (то, что платится на лонге за вычетом того, что получаешь на шорте) превышает `ARBITRAGE_MAX_UNFAVORABLE_FUNDING_PERCENT` (по умолчанию 0.5% за период начисления), пара пропускается с уведомлением — funding начисляется независимо от схождения ценового спреда и может съесть прибыль арбитража. Если одна из двух сделок всё же не проходит (например, биржа отклонила ордер по другой причине), вторая, уже открытая, немедленно закрывается — открытой незахеджированной позиции не остаётся. После открытия бот присылает сообщение со средними ценами входа и **прекращает следить за остальными парами**, отслеживая только цену этой пары. Когда разница цен между биржами опускается ниже 0.3%, обе позиции закрываются по рынку, бот присылает сообщение со средними ценами закрытия и расчётной прибылью (без учёта комиссий и funding), после чего слежение за всеми парами возобновляется.
- **Доступ ограничен**: бот отвечает только пользователю Telegram с юзернеймом `@n1k1tabykov`; все остальные получают сообщение «Бот недоступен» и не могут вызвать ни одну команду.

## Структура проекта

| Файл | Назначение |
|---|---|
| `core/bot.ts` | Точка входа: инициализация Telegram-бота, обработчики команд, запуск слежения за сделками. |
| `core/subscribers.ts` | Хранение chat_id подписчиков на уведомления (`data/subscribers.json`). |
| `core/trade-watcher.ts` | WebSocket-подключение к MEXC (user data stream), декодирование protobuf-сообщений о сделках и рассылка уведомлений подписчикам. |
| `core/mexc-ws/push-data.proto` | Минимальная protobuf-схема для декодирования сообщений MEXC WebSocket (канал приватных сделок). |
| `core/arbitrage-watcher.ts` | Опрос публичных тикеров фьючерсов MEXC и BingX (только когда включена автоторговля или открыта позиция) и запуск открытия/закрытия арбитражной сделки. |
| `commands/` | Классы команд (`Command` — базовый класс, `Balance` — `/balance`, `Status` — `/status`, `Trade` — `/trade`, `Stop` — `/stop`). |
| `commands/utilits/mexc.ts` | Интеграция с MEXC Futures/Spot API: подписанные запросы (HMAC SHA256), баланс, открытые позиции, данные контрактов, открытие/закрытие ордеров, управление listenKey для user data stream. |
| `commands/utilits/bingx.ts` | Интеграция с BingX Futures API: подписанные запросы (HMAC SHA256), баланс, открытые позиции, данные контрактов, установка плеча, открытие/закрытие ордеров. |
| `core/trading-state.ts` | Общее состояние автоторговли: флаг включена/выключена (`/trade`, `/stop`) и текущая открытая арбитражная позиция. |
| `core/arbitrage-trader.ts` | Открытие и закрытие арбитражной сделки (лонг+шорт на 1 USDT/2x), откат при частичном сбое, расчёт прибыли, рассылка отчётов подписчикам. |
| `model/` | Общие TypeScript-типы (MEXC-ответы, баланс, сделки). |
| `system.config.cjs` | Конфиг PM2 для запуска бота на сервере (запускает собранный `dist/bot.js`). |
| `.github/workflows/deploy.yml` | GitHub Actions: деплой на VDS по SSH при пуше в `main`. |

Проект написан на TypeScript и собирается в `dist/` перед запуском. Состояние подписчиков хранится в `data/` (не коммитится, создаётся автоматически).

## Установка

```bash
npm install
```

## Настройка окружения

Создайте файл `.env` в корне проекта (он не хранится в git):

```env
BOT_TOKEN=токен_telegram_бота
MEXC_API_KEY=ваш_api_key_mexc
MEXC_API_SECRET=ваш_api_secret_mexc
BINGX_API_KEY=ваш_api_key_bingx
BINGX_API_SECRET=ваш_api_secret_bingx
```

- `BOT_TOKEN` — получить у [@BotFather](https://t.me/BotFather).
- `MEXC_API_KEY` / `MEXC_API_SECRET` — создать в личном кабинете MEXC (Account → API Management). Для `/balance`, `/status` и уведомлений об арбитраже достаточно права **Read**. **Для автоторговли (`/trade`) обязательно нужно право на фьючерсную торговлю (Trade/Futures)** — без него открытие позиций будет падать с ошибкой авторизации. Если в настройках ключа включено ограничение по IP — добавьте IP сервера, на котором запущен бот.
- `BINGX_API_KEY` / `BINGX_API_SECRET` — создать в личном кабинете BingX. Для `/balance`, `/status` и уведомлений достаточно права **Read**. **Для автоторговли обязательно нужно право Trade на фьючерсы.**

⚠️ Ключи с правом на торговлю дают боту возможность реально открывать и закрывать позиции на бирже. Включайте автоторговлю (`/trade`) только когда осознанно готовы к этому, и держите на аккаунте не больше денег, потерю которых готовы допустить.

⚠️ Автоторговля на BingX рассчитана на аккаунт в режиме **Hedge Mode** (раздельные long/short позиции, стандартный режим для новых аккаунтов). Если на аккаунте включён One-way Mode, открытие позиций будет завершаться ошибкой — переключите режим в настройках BingX (Futures → Preference → Position Mode) перед использованием `/trade`.

Без ключей MEXC/BingX команды `/balance` и `/status` всё равно ответят, но с пометкой о невозможности получить данные по соответствующей бирже.

Торговые пары настраивать не нужно — слежение включается сразу по всем парам аккаунта.

Опционально для автоторговли арбитражем (`/trade`):

```env
ARBITRAGE_POLL_INTERVAL_MS=15000
ARBITRAGE_THRESHOLD_PERCENT=3.2
ARBITRAGE_MAX_UNFAVORABLE_FUNDING_PERCENT=0.5
```

Тикеры для поиска расхождения цен публичные и ключей не требуют, но само открытие/закрытие позиций после `/trade` требует API-ключей с правом на торговлю (см. выше) — без них автоторговля будет только присылать сообщения об ошибках при попытке открыть позицию.

## Запуск

Для разработки (запуск `.ts` напрямую, с автоперезапуском при изменениях):

```bash
npm run dev
```

Для продакшена (сборка в `dist/`, затем запуск):

```bash
npm run build
npm start
```

## Деплой

При пуше в ветку `main` GitHub Actions ([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)) подключается к VDS по SSH, делает `git pull`, `npm ci`, `npm run build`, `npm prune --omit=dev` и перезапускает процесс через PM2 (`system.config.cjs`).

Требуемые секреты репозитория (Settings → Secrets and variables → Actions):

- `SSH_PRIVATE_KEY`
- `SSH_HOST`
- `SSH_USER`
- `SSH_PORT`
- `DEPLOY_PATH`

`.env` на сервере не создаётся деплоем автоматически — его нужно один раз завести вручную в `DEPLOY_PATH` с теми же переменными, что и локально. После изменения `.env` на сервере перезапустите процесс, чтобы переменные подхватились:

```bash
pm2 restart trade-bot
```
